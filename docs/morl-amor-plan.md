# ZBot多目标强化学习（AMOR/MOPPO）引入方案

参考资料：Disney Research视频 [AMOR: Adaptive Character Control through Multi-Objective Reinforcement Learning](https://www.youtube.com/watch?v=gQidYj-AKaA)，论文 [arXiv:2505.23708](https://arxiv.org/abs/2505.23708)，正式版本 [ACM DOI 10.1145/3721238.3730656](https://doi.org/10.1145/3721238.3730656)。

## 结论

适合引入，但不能把“运行中修改标量奖励权重”直接称作MORL。当前 `WalkingReward` 最终仍返回一个加权和，actor和critic不知道权重。AMOR训练的是一张权重条件策略：每个环境每个回合获得不同偏好向量，actor接收偏好向量，critic预测各目标的向量价值，MOPPO用偏好向量将向量优势标量化。训练完成后，用户改变偏好便可零样本切换行为。

当前已完成的任务卡、15项奖励贡献历史和柱状趋势是MORL的观测与交互基础，可以保留；需要新增算法和网络合同。

## ZBot首版目标空间

不直接把18个奖励项全部作为18维Pareto空间。维度过高会导致单纯形覆盖极慢，也让用户难以理解。首版把第二阶段奖励整理为5个“越大越好”的目标，原有有符号权重作为组内先验尺度：

|目标|包含的现有分项|含义|
|---|---|---|
|稳定姿态|足部朝下、足部朝前、默认姿态、机身航向|站稳并保持可控姿态|
|前进效率|前进速度、步长|更快、更有效地前进|
|步态节律|腾空总时长、腾空时间差、小碎步|形成有推进距离的交替步态|
|平滑能耗|动作变化、机身抖动、力矩平方、总机械能耗|减少身体振荡和执行器负担|
|接触与路径|滑脚、累计航向、横向偏移|减少滑移并保持直行|

终止惩罚和存活奖励作为所有目标共享的安全底座，不参与偏好归一化，否则极端偏好可能学会通过快速跌倒逃避负奖励。第一阶段站立课程继续使用固定权重；进入第二阶段后再启用MORL。这样避免随机策略在完整偏好空间中重复出现“弹飞且学不会站立”。

## 网络和算法合同

新增任务ID：`Mjlab-Zbot-6dof-AMOR-Finetune`，从已验证 `model_801.pt` 初始化。

- 外部物理观测仍为26维；保留四元数派生的4维特征。
- actor输入从30维扩为35维：`[原30维特征, 5维偏好w]`，动作仍为6维。旧actor首层权重原样复制，新增5列初始化为0。
- critic输入同为35维，输出从标量改为5维目标价值。
- 每个环境在episode reset时从 `Dirichlet(1)` 采样 `w∈Δ⁵`，回合内固定；transition保存 `(s,a,r_vector,s_next,w)`。
- 对5个目标分别执行GAE，得到向量优势；用 `A_vector·w` 构造并按mini-batch归一化的PPO clipped loss。
- 原始目标量、组内先验尺度、采样偏好和标量化结果分别记录，不能只保存最终加权和。
- 检查点必须保存目标定义版本、偏好采样器、向量critic、观察合同和训练范围；普通PPO检查点不得误作MOPPO续训。

论文使用均匀Dirichlet覆盖完整单纯形。ZBot首轮可先复现该基线，同时额外报告偏好空间边角的失败率；如果极端偏好导致大量跌倒，再引入有明确记录的安全下限或非均匀采样，不能静默改变问题定义。

## 网页交互

仍只保留一处任务卡。选择AMOR任务后，同一任务卡切换为：

1. 五个目标的组内先验尺度；这些值定义训练问题，运行中修改会改变目标语义，默认锁定。
2. 五个非负偏好滑块，始终归一化到100%；训练中用于观察指定偏好环境，回放中用于零样本控制策略。
3. 当前目标向量柱状图、偏好加权后的贡献柱状图，以及最近更新趋势。
4. Pareto视图：选择任意两个目标作为坐标轴，显示评估点、非支配点和当前偏好。

普通PPO任务继续显示现在的有符号奖励权重。界面必须明确区分“修改训练奖励定义”和“选择已训练MORL策略偏好”，防止用户误以为两者等价。

## 分阶段交付

### 阶段A：MOPPO最小闭环

- 5维目标向量、每环境Dirichlet偏好、35维条件actor、5维critic。
- 256环境短训练验证张量形状、checkpoint恢复和奖励/偏好日志。
- 4096环境训练，至少覆盖均衡偏好和5个单目标附近偏好的确定性评估。

验收：同一checkpoint在改变偏好后产生可重复的动作差异；所有偏好测试数值有限；均衡偏好不低于现有站立安全门；检查点可续训。

### 阶段B：Pareto评估与浏览器回放

- 固定偏好集合批量评估存活、位移、速度、滑脚、能耗和横偏。
- 提取非支配解并在网页显示二维投影。
- 结果包导出条件actor；MuJoCo WASM回放提供5维偏好滑块，切换权重不请求Python服务。

验收：下载后的静态结果包可在CPU浏览器中切换偏好；物理周期、目标定义和权重归一化与训练一致。

### 阶段C：高层权重策略

只有阶段A/B证明低层条件策略覆盖了有效行为后，再训练高层策略随状态输出偏好。首版不引入论文的运动窗口VAE和判别器，因为ZBot当前任务是无参考轨迹的行走，不具备相同的运动上下文。高层策略先针对速度命令、扰动恢复和能耗约束，不直接复制角色动作跟踪结构。

## 计算与风险

论文实验使用8192环境、250 Hz仿真、300k次更新，在RTX 4090上每个角色约训练5天。ZBot网络和目标更小，但MOPPO需要覆盖偏好空间，收敛通常慢于固定权重PPO，不能以当前300次更新作为完整训练预算。主要风险是目标尺度失衡、极端偏好导致安全性退化、向量critic实现错误，以及浏览器推理漏传偏好向量；上述风险必须通过目标级回报、单目标端点和均衡偏好三类测试分别检查。
