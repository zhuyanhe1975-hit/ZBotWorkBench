# 页面 CPU 开销优化

暂停状态改为按需绘制：模型、姿态、相机或控件变化才请求一帧；相机阻尼结束后不再保留动画回调或定时器。活动画面最多绘制 30 帧/秒。抗锯齿、像素比和 2048 像素阴影图保持不变，阴影图只在模型、姿态或阴影覆盖区域变化时更新。

阴影相机和接收阴影的地面随机器人在水平面移动，光照方向与阴影图大小保持不变，避免走出起点附近覆盖范围后阴影消失。这与观察相机是否开启跟随无关；暂停或仅转动观察相机不会持续重建阴影。

打开强化学习面板会停止被覆盖实验台的绘制。滚出视口的三维画面不绘制。整个浏览器标签页进入后台时，物理与绘制均挂起；回来后从当前状态继续，不补算离开期间的时间。播放按钮的选择保持不变。

物理循环只在播放期间存在；强化学习只有实际执行了控制步才发布界面状态。PhysX 60 Hz、策略 30 Hz、权重、动作积分、MuJoCo 比较模型都没有改变。

## 测量

同一台机器、隔离 Chrome、1280×800、DPR=1、SwiftShader 软件渲染。每个状态预热 2 秒后采样 5 秒，比较优化前后的静态构建。CPU 为该测试 Chrome 的进程合计，**单个逻辑核心满载算 100%**，不是整机 CPU 百分比；其他 Chrome 与 VMware 未计入。

| 状态 | 优化前 CPU | 优化后 CPU | 降幅 | 优化后 5 秒绘制调用 |
| --- | ---: | ---: | ---: | ---: |
| 实验台暂停 | 660.96% | 7.79% | 98.82% | 0 |
| 回放面板未加载 | 812.08% | 24.78% | 96.95% | 0 |
| 策略加载后暂停 | 927.30% | 6.99% | 99.25% | 0 |
| 策略播放 | 922.83% | 301.32% | 67.35% | 3039 |
| 策略再次暂停 | 988.82% | 7.99% | 99.19% | 0 |

绘制调用计数为 WebGL draw 方法调用数，一帧含多个绘制调用，不是帧数。暂停时 `requestAnimationFrame` 回调计数也为零。原始数据、口径和源文件校验和见 [browser-cpu.json](../results/performance/browser-cpu.json)。硬件加速浏览器的绝对数值会不同；首次资源初始化、浏览器自身后台工作和正在运行的仿真仍有 CPU 开销。

## 验证与维护

- `tests/renderScheduler.test.ts` 覆盖合并刷新、30 Hz 上限、阻尼继续、渲染内再次请求、隐藏/恢复和释放。
- 浏览器验证了空闲零绘制、相机视角和拖动、零时刻模型切换、末端控制器、回放覆盖、单步、重置及暂停时清除轨迹。
- 实际切换到另一标签页后，物理时间与绘制计数停止；回来后继续完成 20 秒策略播放。关闭回放后实验台再次进入零绘制空闲状态。
- `npm test` 包含原来的真实 WASM 行走稳定性测试；本次没有放宽运动判据。
- 隔离测试 Chrome 在每次测量的 `finally` 中退出，并复查对应用户目录的剩余进程数为零。

主要文件：`src/components/SimulationViewport.tsx`、`src/utils/renderScheduler.ts`、`src/App.tsx`、`src/components/RlReplayPanel.tsx`。后续新增直接修改 Three.js 对象的用户操作，须显式请求刷新，不能依赖永久渲染循环。
