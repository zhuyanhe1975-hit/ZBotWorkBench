# 本机 mjlab 强化学习训练

这是可选训练服务。现有静态构型实验台和15组历史策略回放仍可独立使用；只有训练需要本机Python环境。目前支持Linux单机、单任务并发，以及六自由度双足任务的已有策略微调和从零训练。从零训练采用已成功跑通的240 Hz物理、30 Hz控制和8步接触历史；旧60 Hz检查点会被拒绝，避免继续训练不兼容的动力学策略。

## 已配置的行走任务

默认任务是 **6DOF 已有行走策略微调（推荐）**，ID 为 `Mjlab-Zbot-6dof-Walking-Finetune`。它从参考工程的 `2026-09-09_exact-ppo-noentropy/model_801.pt` 初始化，原权重和来源哈希保存在 `training/presets/walking/`，不依赖参考工程的源码或教师文件。

- 完整恢复 Actor、Critic、优化器和第二阶段课程；固定学习率 `1e-5`、熵系数 `0`。
- 物理240 Hz、控制30 Hz、接触历史8步、积分速度参数范围0.8～1.2。
- `QuatFeatureMLP` 保留26维输入，内部计算四元数派生特征，再送入30维MLP；网页执行相同变换。
- 有CUDA环境时默认GPU、256环境、4个CPU线程、100次新增更新，每10次保存，最长3600秒。环境不足时可选择CPU小规模运行。
- “回放参考策略（model_801）”始终播放原始基线，便于与本次训练结果比较。微调不保证越训越好，原始基线不会被覆盖。

参考工程记录三个种子各32/32完成20秒迈步；本次重新评估种子123也是32/32完成，平均前进约3.89米，但接触滑移仍超过原验收阈值。它是可行走的微调起点，并非从零训练成功或完整稳定性验收通过。配置来源见 [预设说明](../training/presets/walking/README.md)。

本机已按上述默认配置实跑100次更新，任务 `cc2e1e96-9859-402f-afe2-30b1bb6eb1b8` 的最终检查点为 `model_901.pt`。种子123、32环境原生评估全部完成20秒回合，平均前进3.87米；WASM单环境连续20秒前进3.60米，最低机身高度0.252米、最大横向偏移0.231米。滑脚仍未通过原生验收，不宣称微调改善了所有指标。结果见 [验证记录](../results/training/walking/README.md)。

“6DOF准静态慢走（实验）”任务ID为 `Mjlab-Zbot-6dof-Quasistatic-Walking`。它从model_801初始化，但使用0.04 m/s低速跟踪、0.2～0.4积分速度范围，以及支撑稳定、机身倾斜、慢步频、双脚腾空、关节速度/加速度、抖动、滑脚和能耗奖励。GPU默认1024环境、1000次更新，每50次保存。短训练只验证配置链路；正式结果必须检查20秒存活、实际速度、步频、双脚腾空比例、滑移和能耗。

## 启动

解释器依次从 `ZBOT_TRAINING_PYTHON`、同级 `../zbot_rl_mjlab/.venv/bin/python`、项目内 `training/.venv/bin/python` 和系统 `python3` 查找。本机已发现同级项目的环境。任务代码和模型已作为有来源哈希的快照放入 `training/tasks/`，worker不需要修改或依赖原训练项目的源码。

```bash
npm run build
npm run training
```

打开 **http://127.0.0.1:8767/?training=1**。已有开发服务器 `npm run dev` 时，也可从顶部“强化学习训练”进入；Vite会将本机请求转发给训练服务。

局域网部署使用 `deploy/Caddyfile`，由同一个 `http://192.168.13.10:8081/` 站点提供静态前端并将 `/api/training/*` 反向代理到回环地址上的训练服务。这样可直接打开 **http://192.168.13.10:8081/?training=1**，训练端口本身仍不监听局域网地址。该入口允许局域网访问者提交和停止训练任务，只应部署在可信网络中。

其他机器可以用独立环境安装 `training/requirements.txt`，然后指定解释器：

```bash
ZBOT_TRAINING_PYTHON=/path/to/python npm run training
```

已验证的版本为mjlab1.3.0、RSL-RL5.2.0、MuJoCo/MuJoCo-Warp3.8.1、Warp1.12.1、PyTorch2.9.1。本机使用CUDA12.8构建的PyTorch；CPU机器可使用对应CPU构建。安装说明和源代码快照说明见 [training/README.md](../training/README.md)。

## 使用流程

1. 打开面板，自动读取CPU、可用内存、GPU型号/显存/负载、Python依赖，以及已知训练目录中的检查点元数据。检测不会自动开始训练。
2. 选择CPU或一张GPU，设置CPU线程数、并行环境数、更新次数、保存间隔、种子和最长运行时间。CPU适合小规模验证；GPU训练仍需要CPU调度。
3. 点击开始。任务按顺序运行，界面显示迭代、奖励、损失、采样速度、曲线、日志及检查点。训练画面默认关闭；点击“显示训练画面”后显示最多9个并行环境，再次点击即可关闭。GPU首轮需要编译Warp内核，启动可能明显慢于后续任务。
4. “停止并保存”会请求在更新边界保存；若尚未完成任何更新，可能没有检查点。无响应进程在宽限期后强制结束，此时只能使用此前已经保存的文件。
5. 选择本服务已有检查点，执行继续训练。更新次数表示本次新增次数；任务、网络和优化器配置从检查点恢复，计算设备和环境数可以重新选择。
6. 训练后点击“用MuJoCo回放训练结果”，或下载完整JSON回放包。离线时在原回放面板选择“mjlab训练结果包”，即可加载模型、权重和对应参数。

## 单一任务卡与奖励权重

训练页只显示一处“任务卡”。没有运行任务时，它编辑下一次训练的配置；选中等待或运行中的任务时，同一张卡切换为实时修改模式。卡片顶部显示物理频率、控制频率、接触历史、初始课程阶段和积分速度范围，下面可修改：

- 第一阶段5项奖励权重；
- 第二阶段16项奖励权重；
- 提前终止惩罚。

权重范围为-100～100，终止惩罚范围为0～1000，奖励项名称和数量不能改变。点击应用后服务原子写入任务目录，worker在当前rollout和PPO更新结束的边界读取，因此同一批数据不会混用两套奖励。新权重从下一次PPO更新生效，任务卡版本、日志和后续检查点都会记录实际配置。停止或完成的任务卡保持只读；可从其检查点续训后再调整。

训练记录中的“奖励分项贡献”使用柱状图显示全部18个去重分项。中间竖线为零，绿色向右表示正贡献，红色向左表示负贡献；数值下方的百分比按当前所有分项绝对贡献之和计算，可直接比较相对比例。每行右侧是最近20次PPO更新的迷你柱状趋势。图表记录的是“原始奖励量×当前任务卡权重”之后的实际贡献，因此运行中修改权重会从生效迭代开始反映在趋势里。

“总机械能耗”使用六个关节的正机械功率 `Σ|τ·q̇|`，默认权重-0.01。RewardManager按控制周期对功率惩罚积分，因此整个episode累计项正比于消耗机械能量；绝对值同时计入驱动和制动功，属于保守能耗代理，不等同于包含电机效率与回馈的电池能量模型。

“小碎步”只在真实落脚事件发生时计算：向前推进不足0.025米和腾空时间不足0.08秒分别形成归一化短缺，两者相加后按默认权重-5惩罚。静止站立以及环境重置后的非落脚帧不会持续扣分。

“机身抖动”比较相邻30 Hz控制步的机身角速度，以及横向/垂直线速度变化；稳定的向前速度被排除。横向和垂直变化使用10倍尺度，默认权重-0.5。环境重置后的第一帧屏蔽，避免把重置跳变误计为抖动。

准静态任务额外使用：目标0.04 m/s、容差0.02 m/s的高斯低速跟踪；COM到当前接触脚支撑中心的0.08 m尺度奖励；机身倾斜、双脚腾空、关节速度/加速度惩罚；目标1.2秒、容差0.3秒的落脚周期惩罚。快速前进奖励权重在该任务中为0，避免同时鼓励越快越好。

滑脚分项使用每只脚与地面之间“最大接触力”的单个代表接触点，不使用8槽接触缓存。接触点速度按 `vCOM + ω×(p接触-pCOM)` 计算并投影到接触切平面，只计入接触力大于1 N的点；速度使用阈值0.08 m/s的Huber惩罚，降低异常冲击对PPO的支配。该定义比足部质心水平速度更接近实际脚底滑移。

关闭网页不结束训练，重新打开可查看任务；需要结束时使用停止按钮。关闭训练服务会停止自己的worker并取消排队任务。历史Isaac检查点不能直接续训；`QuatFeatureMLP` 仅在上述固定行走预设及其后续检查点中支持，以免混用观测与网络语义。

## 资源与进程管理

- 服务仅绑定127.0.0.1；接口具有会话令牌、来源检查和路径限制。Vite代理限制本机调用；生产部署的Caddy代理则把请求约束在8081同源入口，直接访问8767仍只允许本机。由于8081入口可控制训练任务，必须仅在可信局域网内开放。
- 扫描范围和深度有上限；检查点扫描只读取元数据。外部历史权重可被发现，但第一版仅允许续训本服务生成的检查点。
- 默认扫描已知同级训练目录；可用环境变量 `ZBOT_TRAINING_SCAN_ROOTS='["/path/to/models"]'` 指定最多10个目录。浏览器不能任意扩大扫描范围。
- 资源探测有缓存；前端任务轮询2秒、资源轮询10秒，标签页隐藏时停止轮询。训练页面覆盖底层三维视图时不继续重绘。
- 实时训练画面直接采样当前mjlab批次的刚体姿态，每次PPO更新上传一帧；它使用训练MJCF中的真实ZBot网格、颜色和实体尺寸。画面开启时，页面在一个WebGL场景中实例化最多9个环境，共用一份几何资源。画面关闭或训练面板退出时，worker停止把GPU姿态复制回CPU，浏览器销毁该WebGL场景，让后台训练保持更高速度；完整训练环境数不受影响。
- 连续画面使用本机事件流推送真实姿态，worker最多45 Hz采样。浏览器收到一帧就立即显示一帧，不补帧、不插值，也不另行运行策略。PPO更新参数期间仿真状态本身不推进，因此画面会保持最后一个真实状态，直到下一次环境步到达。事件流断开时服务会自动关闭该任务的画面采样。
- 每台实体以mjlab固定的 `env_origin` 计算真实位移，再加上固定的九宫格布局偏移。相机位置和朝向在播放过程中保持不变，不跟随机器人；根节点前进、侧移、高度、跌倒和环境重置均直接来自状态流。
- 单个worker拥有独立进程组、线程设置、输出目录和运行时限。停止只操作本服务自己的进程，不终止桌面、浏览器或其他训练程序。
- Linux下CPU线程选择也限制worker的CPU亲和性；GPU选择按物理设备隔离。服务锁阻止两个实例同时操作同一任务目录。
- 显存信息用于设备选择和调整并行环境数；当前不承诺GPU百分比硬限额，也不自动将显卡占满。

任务和结果保存在被Git忽略的 `.training/jobs/<任务ID>/` 中，包括请求、任务状态、日志、`checkpoints/model_N.pt`、版本信息及 `bundle.json`。完整训练日志另保留TensorBoard格式，不要求云账号。

## 训练与回放的一致性

历史Isaac网络继续用PhysX；新mjlab结果强制使用其自带的MuJoCo模型和物理/控制周期。结果包包含完整XML、带独立文件名前缀的OBJ资产、初始状态、关节名、积分速度、MLP权重、必要的特征变换标识和软件版本。浏览器不会套用历史PhysX模型，也不会改变训练的60Hz或240Hz物理频率。

回放相机跟随机器人时，有限的grid载体覆盖根节点附近区域，但纹理坐标按0.5米网格反向补偿载体位移，因此参考线固定在MuJoCo世界坐标中。训练导出的初始姿态即使带有并行环境偏移，网格既不会从画面消失，也不会跟随机器人滑动。

本机已经实跑CPU/GPU短训练、优化器续训和停止保存，并将真实训练结果包在MuJoCo WASM中回放20秒。**少量更新只证明训练链路可用，不代表策略已学会稳定行走。** 正式训练仍需足够迭代和独立运动评估。GPU Warp与CPU/WASM之间的数值及接触差异也需逐任务验证。

当前不包含多机训练、多GPU分布式训练、任意任务代码上传、全部15个Isaac任务的重训练或任意自定义特征网络导出。
